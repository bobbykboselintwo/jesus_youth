I'd make the backend check these exact conditions.


### Rule 2 — Amount

Extract the rupee amount.

For example:


Then:

```python
if amount != 100:

```

So:

```text

₹99    → REJECT
₹100   → ACCEPT
```

That's exactly what you asked for.

# Rule 3 — Recipient

Normalize the OCR text first.

For example OCR might return:

```text
ABRAHAM JOSEPH
THADATHIL
```

Convert it to:

```text
ABRAHAM JOSEPH THADATHIL
```

Then compare against:

```text
ABRAHAM JOSEPH THADATHIL
```

You should allow minor OCR errors.

For example:

```text
ABRAHAM JOSEPH THADATHIL
ABRAHAM JOSEPH THADATHIL
```

→ exact match.

But:

```text
ABRAHAM JOSEPH THADATHIL
ABRAHAM JOSEPH THOMAS
```

→ reject/manual review.

I would **not use loose fuzzy matching for automatic approval** because that could accidentally approve a payment to another person.

# Very important: don't permanently save screenshots on Render

This is especially important for your setup.

You're using the **Render Free web service**, which currently has **512 MB RAM**, and Render says the free service has an **ephemeral filesystem**. Files uploaded to the local filesystem can disappear when the service restarts, redeploys, or spins down. Free web services also don't support persistent disks. ([Render][1])

So I would **not** do this:

```text
/uploads/
    student1.jpg
    student2.jpg
    student3.jpg
    ...
```

Don't build a screenshot storage system inside your Render container.

Instead:

```text
Student
   ↓
Upload image
   ↓
RAM / temporary file
   ↓
OpenCV
   ↓
Tesseract
   ↓
Extract data
   ↓
Validate
   ↓
DELETE IMAGE
   ↓
Return result
```

That means the screenshot exists only long enough to process it.

# OpenCV's job

OpenCV doesn't need to "understand" the payment.

It should prepare the screenshot for OCR.

For example:

```text
Original screenshot
        ↓
Resize
        ↓
Grayscale
        ↓
Contrast enhancement
        ↓
Noise removal
        ↓
Thresholding
        ↓
Tesseract
```

Something like:

```python
image = cv2.imread(path)

gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)

gray = cv2.resize(
    gray,
    None,
    fx=1.5,
    fy=1.5
)

processed = cv2.threshold(
    gray,
    0,
    255,
    cv2.THRESH_BINARY + cv2.THRESH_OTSU
)[1]
```

Then:

```python
text = pytesseract.image_to_string(processed)
```

# Your validation engine can be tiny

Conceptually:

```python
EXPECTED_NAME = "ABRAHAM JOSEPH THADATHIL"
EXPECTED_AMOUNT = 100

def validate_payment(payment):

    if not payment.payment_success:
        return "REJECT"

    if payment.amount != EXPECTED_AMOUNT:
        return "REJECT"

    if not recipient_matches(
        payment.recipient,
        EXPECTED_NAME
    ):
        return "REJECT"

    if not payment.has_upi:
        return "MANUAL_REVIEW"

    return "APPROVED"
```

That's basically the heart of the system.

# The biggest limitation

There is one thing I want you to be very clear about:

**OCR + OpenCV cannot mathematically prove that ₹100 was actually transferred.**

It can establish:

> "This screenshot appears to show a successful ₹100 UPI payment to ABRAHAM JOSEPH THADATHIL."

It cannot establish with certainty:

> "₹100 definitely reached the bank account."

Someone could theoretically edit a screenshot.

So for your current requirement, I'd call this:

**Automated screenshot verification**

rather than true:

**Payment verification**

True payment verification would ultimately come from your payment/UPI provider or your bank-side transaction records.
